Design A: publish a prebuilt directory

Selected design. Selected source implementation; no deployment is claimed. The cookie migration must land first. This is a general repository feature; no Effeck owner, repository, hostname or content is compiled into the product.

One product authority

The existing backend owns repository authorization, publication manifests, active revisions, domain claims and transfer-proof consumption. Add typed ports for immutable publication storage, a host directory and the certificate provider. Compose them into the current repository services and routes. The edge receives a typed Host resolution and reads assets; it stores no product authority and implements no additional API proxy. In a cell deployment, the directory selects a cell and that cell uses the same publication and domain services.

Publication and storage

smthrs site publish <dir> is a command in the normal CLI command/flow infrastructure, not a separate executable. The owner builds locally or in an existing authorized repository flow. The CLI rejects symlinks, traversal, duplicate normalized paths, reserved paths, excessive file count and bytes. The backend repeats all checks, verifies each uploaded digest and size and rechecks owner authority before activation. Uploading does not run repository code on the edge or apex.

The implementation reuses the existing install_settings store under sites/ keys, guarded by ordered transactional advisory locks. No new tables or migrations are needed. The durable model is a repository site, immutable publication manifests and globally unique host claims, with one active-version pointer. Upload interruption cannot move that pointer. Activation compares the previous version and commits atomically. Rollback is a pointer change to a verified retained version, never a rebuild or mutable overwrite. The initial implementation retains all publication versions; it does not automatically collect old versions or immutable blobs.

Names and origin isolation

Only repositories whose verified GitHub organization identity appears in operator configuration may obtain a smithers.sh subdomain. Prefer immutable organization IDs; a user-created namespace with the same spelling grants no eligibility. Names use a canonical lowercase DNS-label grammar and transactionally locked host keys unique across owners. The repository name is the default requested name for every organization, including an organization/repository named smithers. Everyone else gets custom domains only until a separate user-content domain is on the public suffix list.

The checked-in docs redirect configuration contains 48 unique routed subdomains at this revision, not 49. Reserve every one directly from that inventory, plus build (the build-cache hostname documented by the docs generator), and the deployment infrastructure names. A regression test must compare the allocator inventory with wrangler.docs-redirect.jsonc. Never release a docs or infrastructure reservation when a site is removed.

Domain lifecycle

Owner-only add reserves a normalized hostname globally, creates a Cloudflare Custom Hostname with managed SSL and persists its identifier and exact ownership/DCV records. Return the actual record names and values; do not synthesize a presumed TXT token. Refuse IPs, ports, credentials, wildcards, public suffixes and reserved Smithers origins. CNAME target belongs to deployment configuration.

Use the provider response and DNS verification to move through pending ownership → verified → certificate active → bound. Host resolution requires both custom-hostname status=active and ssl.status=active, plus customer DNS pointing at the configured SaaS target. Explicit domain verification and on-demand resolution after 60 seconds refresh status, renewal/DCV records and errors. Cloudflare owns managed renewal; no new scheduler is introduced. Cloudflare manages renewals; expose new required records and fail closed when certificate/hostname status is no longer active. Removal first commits an inactive tombstone and revokes pending transfers; only then delete the provider hostname/certificate. Retry uncertain provider deletion with the saved provider ID. An add after removal gets a new ownership proof, never the old active binding.

Central sign-in

Only smithers.sh performs GitHub OAuth. The destination starts an explicit human sign-in and writes a host-only random state cookie. The backend records a normalized return origin that currently resolves to this site, an approved relative path, a state digest and a short expiry. The central callback checks GitHub state, then issues a random, single-use, audience-bound proof whose digest and user identity are stored durably. Redirect only to the stored verified destination. The proof may travel in the completion URL; the session credential never does. Set no-store and Referrer-Policy: no-referrer, consume proof atomically with the destination state cookie, recheck active binding and existing roster/repository authorization, mint a fresh destination session and redirect to a clean relative URL. Refuse replay, stale proof, wrong Host, missing state and encoded/network-path redirects. No static page visit signs a person in.

Origins, removal and cells

Extend the public allowed-origin seam using active verified host records; remove the origin immediately on unbind. Do not use an arbitrary Origin request header or wildcard allowlist. The self-host seam already loads public_origins through InstallAddress. The private Helm allowed-origin claim at values.yaml:157 is unverified: this lane did not open the private repository. Private deployment composition must supply the host-directory/certificate/blob adapters, central identity origin, trusted proxy configuration and provider credentials. Cells change the host-directory adapter and assertion audience, not the product state model or repository APIs.

Provider contract verified against official Cloudflare documentation: Custom Hostnames API operations and readiness, ownership records and delegated DCV, and safe removal.
