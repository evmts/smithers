## What

A full-screen priority queue of everything Will can decide or review, served by the maintainer app at `http://localhost:4747/queue` (`node apps/maintainer-site/serve.mjs`, no dependencies, bound to 127.0.0.1). Will works it top to bottom without leaving the page or the keyboard. The contract is scratchpad `final/QUEUE-SPEC.md` (the lead, 14:00).

```
curator (loop, 5 min) --writes--> queue/queue.json  (atomic rename)   --+
                                  queue/coverage.json (every file)      |
                                                                        v
Will <--keys--> /queue page <--SSE /api/events-- serve.mjs  <--reads----+
                     |
                     +-- POST /api/answer --> queue/answers.jsonl (append, fsync)
                                                  |
                    lead reads it live: a change request -> a fix agent
                    fix lands -> curator adds a `verify` item (priority 960)
```

- **One item fills the screen.** Item kinds: `decision`, `question`, `code`, `design`, `gif` and `verify`. Every item has a text box; drafts survive a reload.
- **Keys:** `1` to `4` choose an option, `a` approve, `r` request changes, `l` later (24 h), `u` undo, `i` or `/` type, `Esc` leave the box, `⌘Enter` send, `j`/`k` scroll, `J`/`K` next or previous file, `n`/`p` media, `o` open a file inline, `f` full screen, `?` the key sheet.
- **Order** (the curator recomputes priority on every pass): blockers; checks of fixes made from Will's feedback; design decisions that change work in progress; feature GIFs; designs; code review in groups of related files, covering every file, flows first. A file that changes after Will reviewed it comes back.
- Code shows inline with line numbers, so Will can write "L42: …". Designs render in a sandboxed frame; GIFs play in place. `GET /api/file` serves only files under `~/smithers` (never `.jj`, `.git`, `node_modules`, `.env*` or secret names) and `~/Desktop/smithers-mvp/gifs`.
