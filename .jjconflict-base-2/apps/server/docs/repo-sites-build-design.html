Design B: build sites through Smithers

Alternative considered; not selected for the initial implementation. This is a source proposal, not an implemented or deployed capability. It shares the complete domain, routing and identity contract of Design A.

Build path

owner chooses pinned repository revision + declared build target
       ↓ existing typed repository flow / admitted workspace
       ↓ approved dependency graph + bounded command / output directory
       ↓ verified static output + immutable manifest
       ↓ the same publication/activation service as Design A

Use the existing flow runtime, workspace admission and artifact service. No new build service, branch build root or edge execution model. A build runs as an authorized repository action with the repository’s existing trust, secrets and compute policy. The build flow pins revision, toolchain, approved dependencies, output directory and build receipt. It cannot publish arbitrary filesystem files, widen a secret grant or build an untrusted contributor change using owner authority. The UI acknowledges immediately and follows the actual durable run through build and publication; launch acceptance is not completion.

Storage and atomicity

R2 is a possible BlobStore adapter. Workers Assets continue to carry the Smithers application bundle; generating a deployment for each repository publication adds unnecessary release authority. Serving the repository host’s mutable branch filesystem cannot provide rollback or an immutable revision. Both designs publish create-only objects and immutable manifests to the shared product blob port, verify checksums/sizes, then compare-and-swap the active version. A failed/cancelled build or upload leaves the previous site active. Rollback activates an existing verified manifest without rebuilding. Persist the build receipt as provenance alongside the publication, never as the condition for serving mutable output.

Routing, names and domains

Both designs require fail-closed Host resolution first, then the unchanged /api proxy, reserved app prefix/bundle paths, exact active-manifest static paths and finally the app at an unclaimed path with a trusted repository boot projection. No file-extension guesses. Explicit index aliases preserve existing URLs. A build cannot claim /api or the configured /repo/ prefix.

The global lowercase name allocator checks operator-configured verified first-party organization IDs, database uniqueness, every docs-redirect hostname and infrastructure reservations. Non-first-party repositories use verified custom domains only. No arbitrary content runs on the apex or another same-site Smithers hostname. At this revision the redirect inventory contains 48 names; reserve those plus build and the remaining infrastructure names rather than silently assuming a 49th redirect exists.

Owner domain add reserves a global hostname and persists the Cloudflare ID and exact ownership/DCV TXT or CNAME records. Bind only after ownership, certificate status and customer routing DNS are active. Reconcile renewals through the provider API and show any new required DCV records. Remove by tombstoning the product binding and proofs first, then retry provider deletion. Wrong, pending, removed and certificate-inactive hosts cannot serve content or APIs. An unrelated repository cannot reuse an active claim.

Central identity and allowed origins

Keep OAuth at smithers.sh. A human starts sign-in at the destination, obtaining a random host-only state cookie. The central callback may issue a short-lived single-use proof for that exact active Host and validated return path. Consume proof and state atomically, recheck binding and the existing repository/roster policy, then mint a host-only destination cookie. Never put the session token in a URL. Reject scheme-relative, encoded-slash/backslash and external return URLs, stale state, wrong audience, expiration and replay. Do not sign in on page load.

Active domain resolution supplies allowed origins to the backend; removal immediately revokes this origin. Do not widen a wildcard static Helm allowlist. The public InstallAddress seam is verified locally; the private values.yaml:157 claim is unverified and no private source was read. In a cell deployment the directory maps Host to the deployment-controlled cell origin and assertion audience. The cell retains the same product authorization, publication storage contract and site flow.

Why select A

Publishing prebuilt bytes establishes exact static URLs, app coexistence, domain ownership and identity isolation without making a build machine prerequisite. Smithers builds should be a repository-owned composition using the same publish operation, not a competing publisher. A need for managed builds can be met after this slice using existing runtime and build flows. No new npm, Go or Cargo dependency is required by the selected architecture.

Acceptance and deployment boundary

In addition to A’s composed edge/domain/central-auth HTTP tests and browser journey, B would need tests for failed build, cancellation, dependency refusal, secret withholding, symlink output escape and restart between build completion and activation. Neither helper tests nor an accepted flow launch prove publication. Only the DRI may deploy or publish Effeck content. This lane supplies source and a runbook; no Cloudflare/GCP/Helm/DNS mutation is authorized.
